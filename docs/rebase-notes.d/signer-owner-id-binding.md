## Tiny-model signer bound to the vidiko owner ID (2026-10-09)

- `core/src/dnn/model_loader.c::vmaf_dnn_verify_signature()` confines the
  registry's `sigstore_bundle` path to the registry directory, reads the bundle
  once (`slurp_json_file()`), checks it with
  `core/src/dnn/signer_identity.c::vmaf_dnn_signer_check_bundle()`, writes the
  checked bytes into a mode 0700 directory created with `mkdtemp(3)` (opening
  `bundle` inside it with `O_EXCL|O_NOFOLLOW`), and passes that private file to
  cosign with `VMAF_DNN_SIGNER_IDENTITY_REGEXP` and
  `VMAF_DNN_SIGNER_OIDC_ISSUER` from `signer_identity.h`. **On sync**: model
  verification is fork-only (ADR-0211); keep the check before cosign, the
  private `mkdtemp(3)` directory copy, and the anchored expression.
  `signer_identity.c` is in `dnn_sources` and in every test or fuzz target that
  compiles `model_loader.c` directly.
- When the organisation is renamed, the login in
  `VMAF_DNN_SIGNER_IDENTITY_REGEXP`, `vmaf_dnn_signer_identity_allowed()` and
  the guides changes; `VMAF_DNN_SIGNER_OWNER_ID` does not. A move to another
  organisation changes it: the 2026-11-20 move to `vidiko` changed it from
  `288567244` to `340303765`, and `core/test/dnn/gen_signer_fixtures.py` keeps
  the old value as `PREVIOUS_OWNER_ID`, a refused case.
- `core/test/dnn/signer_fixtures.h` is generated by
  `core/test/dnn/gen_signer_fixtures.py` from a release bundle; do not edit it.
- The `k_schema` tables in `core/src/dnn/signer_identity.c` hold the Sigstore
  bundle v0.3 fields that `vmaf_dnn_signer_check_bundle()` accepts. **On
  sync**: when the bundle format gains a field, add it to its table and a case
  to `core/test/dnn/test_signer_identity.c`; an unknown field fails closed.
